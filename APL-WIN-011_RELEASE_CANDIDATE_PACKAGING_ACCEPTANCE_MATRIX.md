# APL-WIN-011 — Release Candidate packaging & acceptance matrix

## Status

Implemented for the Windows productization track. Final acceptance is machine-generated by `tools/windows_rc_acceptance.ps1` and is a prerequisite for Gate R6.

## Canonical RC artifacts

For product version `X.Y.Z`, exactly two Windows product artifacts are eligible for RC acceptance:

1. `Arvectum-Proxy-Launcher-X.Y.Z-windows-x64-portable.zip`
2. `Arvectum-Proxy-Launcher-X.Y.Z-windows-x64-setup.exe`

The portable and installer tracks are built from the same application executable and the same canonical `VERSION`.

A setup file ending in `-synthetic-predecessor.exe` is a CI lifecycle fixture only. It is forbidden as an accepted RC artifact and must never be uploaded as a product release asset.

## Acceptance matrix

| Area | Acceptance criterion | Automated evidence |
|---|---|---|
| Canonical naming | portable/setup filenames exactly match `VERSION` and release policy | `artifact.portable.name`, `artifact.setup.name` |
| Fixture isolation | accepted setup is not a synthetic predecessor | `artifact.synthetic.excluded` |
| Application identity | company/product/description/original filename exact | `exe.*` checks |
| Application version | `ProductVersion == VERSION`; numeric `FileVersion == MAJOR.MINOR.PATCH.0` | `exe.product_version`, `exe.file_version` |
| Setup identity | company/product/description exact | `setup.*` checks |
| Setup version | setup product/file version matches canonical product version | `setup.product_version`, `setup.file_version` |
| Portable provenance | `out/build-result.json` exists, matches `VERSION`, and its ZIP hash matches the final ZIP | `portable.build_manifest.*` |
| Portable contents | ZIP contains only the approved five files | `portable.contents` |
| Binary identity | executable inside portable ZIP is byte-identical to the canonical built executable | `portable.exe.identity` |
| Internal integrity | package `SHA256SUMS.txt` matches the packaged executable | `portable.internal_sha256` |
| User-facing cleanliness | portable README and `INSTALL.txt` expose no internal P0/RC milestone labels | `portable.readme.no_internal_milestone`, `docs.install.no_internal_milestone` |
| Lifecycle | fresh install/smoke, upgrade, repair and uninstall all PASS | `lifecycle.*` |
| Persistent state | upgrade/repair/uninstall preserve persistent configuration | `lifecycle.configuration_preserved` |
| Foreign state | uninstall preserves foreign startup state | `lifecycle.foreign_startup_preserved` |
| Product docs | APL-WIN-010..013 and Gate R6 documents are present | `docs.*` |

Any failed row makes RC acceptance fail closed.

## Acceptance output

The verifier writes:

- `out/windows-rc-acceptance.json` — structured PASS/FAIL matrix and failure IDs;
- `out/windows-rc-SHA256SUMS.txt` — SHA-256 of the final portable ZIP and setup EXE.

These are QA/release-evidence files. The canonical public release workflow remains governed by `RELEASE_POLICY.md`.

## Signing boundary

The acceptance JSON records that production embedded signing is not yet activated. This is deliberate: Gate R6 verifies Windows productization without fabricating a signing claim. The Russia-first signing track remains independently governed by APL-REL-009/APL-REL-010.
